# JerkLog

Habits · Training · Nutrition。面向成年用户的本地优先记录工具。

**当前为 Phase 1B：Training Lab。保留 Phase 1A 的 Habits；Nutrition 继续占位。**

## 启动与检查

需要 Node.js >=22.18 与 npm；CI 使用 Node 22.18.0。

```sh
npm ci
npm run dev
npm run lint
npm run typecheck
npm run test
npm run build
npm run preview
```

构建后运行 `npm run test:e2e`，使用本机安装的 Google Chrome，自动管理 4173 端口的本地预览，覆盖桌面与移动视口。固定使用同一浏览器、协议、主机和端口访问本地记录。

## Training Lab

- **动作**：13 个离线内置动作，名称、主要肌群、器械及备注；搜索/筛选；创建、编辑和删除自定义动作。被计划引用的动作需先移出计划再删除；历史快照保留。内置动作作为参考，不允许直接修改或删除。
- **计划**：新建、查看、编辑、复制、归档/恢复、确认删除。全身、上下肢、推拉腿和胸背肩腿四分化模板均复制为独立可编辑日程。可添加休息日、任意命名日程、调整日程和动作顺序、计划组数/次数范围及备注，不绑定固定星期。
- **当前训练**：从计划训练日或自由训练开始；记录每组动作、次数、kg、可选 RPE/RIR 和备注；修改/删除组，保存训练备注；暂停、恢复、完成或确认放弃。一个未完成训练存在时不再重复创建新训练。
- **历史**：按完成时间分页显示计划/日程名称快照、动作名、组数、负重、强度、备注及有效计时。修改、归档或删除计划/动作不追溯改写已开始训练的快照。已完成训练在本阶段只读，组的修改/删除发生在完成前。
- **统计**：本周完成次数、累计完成次数、最近训练日期和每次训练的负重容量，均来自 IndexedDB。周一当地零点起算，以完成时间计数，排除未来时间。
- **主题与文案**：沿用深浅色、系统主题和整活/专业文案；模式不改变训练数据或统计。四个视图均支持键盘、标签、错误提示与空状态。

## 训练数值约定

用户输入/显示单位为 kg，最多三位小数；数据库同时保存整数克数，容量用 `整数克数 × 次数` 累计后换算 kg·次。自重或无负重组的重量保存为 null，不估算体重，不把未知负重伪装为 0；这类组不计入负重容量。明确输入 0 kg 的负重组可记录，容量贡献为 0。

容量只是描述性指标，不代表全面训练刺激、恢复、热量或健康。RPE 支持 1–10、步长 0.5；RIR 支持 0–10 整数，可都不填，不能同时填写。计划是示例，不是统一处方；注意热身与休息，按自身能力调整。

开始/暂停/恢复/结束使用持久的 UTC 时间戳及活动时间段。有效计时不包含暂停时间，页面刷新不会重置计时。新建组的稳定 ID、同步操作锁及数据库内 1.5 秒相同组提交保护共同防止意外重复写入。不同组内容可连续录入；相同组在冷却后可再次记录。跨标签页修改冲突会提示重新读取，不静默覆盖。

## Habits 与隐私

保留 Phase 1A 的一键记录/补录、编辑、删除/撤销、实际统计、趋势和月历；本次不改写该模块业务代码。所有私人记录只存在当前浏览器 IndexedDB。无登录、云端、遥测、广告、第三方统计或上传请求，不把记录写入 URL 或控制台。Training 不读取 Habits 数据推断训练或健康。

本地存储不是加密，清除站点数据可能丢失记录。备份、导入和 PWA 离线冷启动未实现。仅作成年用户自我管理，不替代医疗建议。
