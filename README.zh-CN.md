# JerkLog

Habits · Training · Nutrition。面向成年用户的本地优先记录工具。

**当前为 Phase 1C：Nutrition Lab。保留已合并的 Habits 与 Training。**

## 启动与检查

需要 Node.js >=22.18 与 npm；CI 使用 Node 22.18.0。

```sh
npm ci
npm run dev
npm run lint
npm run typecheck
npm run test
npm run build
npm run preview
```

构建后运行 `npm run test:e2e`，使用本机安装的 Google Chrome，自动管理 4173 端口的预览，覆盖桌面与移动视口。请固定同一浏览器、协议、主机与端口访问自己的记录。

## Nutrition Lab

- **食品库**：6 条经独立核对的 USDA SR Legacy 数据，显示 FDC/NDB 标识、原文、来源、发布日期与 CC0 许可；搜索、生熟筛选。自建食品支持增改、归档/恢复、确认删除，区分标签与用户输入来源。可明确填写每份克数；没有定义时只允许克数。不暗中换算生熟食物。
- **饮食日记**：早餐/午餐/晚餐/加餐，显式克数或已知份量，按所选当地日期查看，修改份量/日期/餐别、确认删除。记录时保存来源和营养快照，改删食品库不会追溯改写日记。
- **计算**：从实际记录计算单条、每餐和每日 kcal、蛋白质、碳水、脂肪；未知保持 null，部分已知标明不完整，不用 4/4/9 覆盖食品热量。仅显示时舍入。
- **目标**：热量和三大营养素均可独立设置、修改、清空；无目标不伪造进度。可选成年能量估算器需要自愿填写参数，明确粗略活动倍数与适用限制，只在主动点击后填入草稿，再单独保存。身高、体重、年龄等输入不持久化。
- **饮食想法**：默认关闭，依据明确方向、忌口与已知饮食给出无定量组合及替换；可隐藏，不诊断缺乏，不使用 Habits 或 Training 数据推导营养。
- **体验**：沿用深浅色与整活/专业文案；加载/空/错误状态、Toast、键盘对话框和移动布局。事务、版本冲突检查与 1.5 秒同内容防重复保护处理失败与多标签页操作。

准确食品数值、来源及覆盖边界见 [FOOD_SOURCES.md](FOOD_SOURCES.md)。完整功能、文件清单、迁移证据、测试与限制见 [Phase 1C 验收报告](docs/ACCEPTANCE_PHASE_1C.md)。

## 已有模块与数据安全

Habits 保留一键记录/补录、编辑、删除/撤销、实际统计、趋势和月历。Training 保留离线动作、自建动作、可编辑训练计划/日程、组记录、暂停/恢复、历史快照与统计；已完成训练在本阶段只读。训练细节见 [Phase 1B 报告](docs/ACCEPTANCE_PHASE_1B.md)。

数据库 schema v4 在原 v3 上向前迁移，保留全部旧表，不删库、不重置。非空 Habits、撤销状态、Training、Settings 和旧 Nutrition 迁移及故障回滚均有测试。旧摄入快照按原克数换算，不用当前食品值覆盖历史；缺失信息保留为未知。详见 [架构](docs/ARCHITECTURE.md) 与 [隐私说明](docs/PRIVACY.md)。

所有私人记录默认只保存在当前浏览器 IndexedDB。无账号、云端、遥测、广告、第三方统计或食品运行时 API；不上传记录，不写入 URL 或控制台。本地存储不等于加密；清理站点数据可能丢失记录，备份/导入尚未实现。

现有项目未配置 Service Worker，未实现 PWA 离线冷启动；已加载页面的离线读取/模块导航已测试。真实手机、Safari 与大规模记录性能未验收。浏览器测试只在隔离上下文阻断本机 Kaspersky 注入脚本，未关闭或修改系统防护。截图与测试均使用合成数据。
